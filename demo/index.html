This paragraph and the headings above use foundation/typography.css, applied to native tags and driven by tokens. A prose link sits inside it. The full specimen sheet, every role, scale step, weight and line height, is on the typography page.

Links are the sheet's job, not a component's. The bare element already carries the treatment; .neuwo-link states it explicitly for an anchor whose surroundings strip link styling, and .neuwo-link--hover-green swaps the hover colour to the brand green. Both underline at rest and carry the underline into the hover colour with them.

The page defines a hostile .btn class rule and a hostile button element rule. Neither reaches the buttons, which render into their own light DOM.

Copy to clipboard

<neuwo-copy> wraps anything whose text is worth pasting and puts a control in the corner. The page defines a hostile .copy rule, so a leaked shadow root would show a wide pink square instead of the control. The code panel in the Markdown section above is wrapped the same way.

The wrapped content stays in the light DOM, which is the point: the panel keeps the .neuwo-markdown pre styling and any syntax colouring the page applies. Only the control is encapsulated. It copies textContent, so nothing has to name the source. 

curl -X POST https://api.neuwo.ai/v1/classify \
  -H "Authorization: Bearer $NEUWO_TOKEN" \
  -d '{"url": "https://example.com/article"}'

The copied event will report here.

Not only for code. A deal ID exists to be pasted into a DSP, so wrapping one is the other obvious use, and it needs no attribute to say what to copy:

NEUWO-CTX-000123

This one shows the honest limit of a corner overlay: the control assumes a panel with room to spare, and a chip has none, so it would sit on top of the identifier. The library owns no box, so the clearance is the consumer's, and --neuwo-copy-inset pulls the control in to match the smaller target: 

.copy-chip {
  display: inline-block;
  padding-right: 2rem;
  --neuwo-copy-inset: 0.125rem;
