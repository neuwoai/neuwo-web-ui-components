Typography (opt-in stylesheet on native elements)

This paragraph and the headings above use foundation/typography.css, applied to native tags and driven by tokens. A prose link sits inside it. The full specimen sheet, every role, scale step, weight and line height, is on the typography page.

Links are the sheet's job, not a component's. The bare element already carries the treatment; .neuwo-link states it explicitly for an anchor whose surroundings strip link styling, and .neuwo-link--hover-green swaps the hover colour to the brand green. Both underline at rest and carry the underline into the hover colour with them.

The page defines a .btn class rule and a bare button rule, and the two controls below are plain buttons outside any component, so you can see the rules are live. Page rules of one class or less, other than rules on the library's own neuwo- classes, do not reach components, because the reset matches their template nodes at one-class weight. A rule that is more specific than one class does, which is how a host restyles a component.

Copy to clipboard

<neuwo-copy> wraps anything whose text is worth pasting and puts a control in the corner. The page's bare button rule does not reach it. The code panel in the Markdown section above is wrapped the same way.

The wrapped content stays as authored inside .neuwo-copy__content: the panel keeps the .neuwo-markdown pre styling and any syntax colouring the page applies. It copies the text of that wrapper, so nothing has to name the source. 

curl -X POST https://api.neuwo.ai/v1/classify \
  -H "Authorization: Bearer $NEUWO_TOKEN" \
  -d '{"url": "https://example.com/article"}'

The copied event will report here.

Not only for code. A deal ID exists to be pasted into a DSP, so wrapping one is the other obvious use, and it needs no attribute to say what to copy:
