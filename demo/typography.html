Foundation

Neuwo typography

Every heading, paragraph and link on this page is styled by foundation/typography.css alone, driven entirely by the tokens in foundation/tokens.css. Nothing here is a component: typography is an opt-in stylesheet on native elements, so a consumer links it and its own markup inherits the Neuwo type language.

Tokens and fonts come from a linked stylesheet, or from neuwo-standalone.js on a page that can only add a script. Typography is only in neuwo.css: global element rules are intrusive, so linking them is the consumer's decision.

How to load it

Three published entry points, pick one:

neuwo.csstokens + typography <link rel="stylesheet" href="/neuwo/neuwo.css">
foundation/tokens.csstokens only For a consumer that keeps its own element styling.
foundation/typography.csstype only Needs the tokens present, from neuwo.css or foundation/tokens.css.

The @font-face rules are in the stylesheet. Preload the files from /neuwo/fonts/ to avoid a swap on first paint.

Contextual audiences

Reach the right page, not the wrong person

This is the same recipe neuwo-badge inlines. A shadow root cannot use a document class, so the badge repeats it from the same tokens rather than importing it.

In context

Classification API

Every page, understood in milliseconds

Neuwo reads a page the way a person would: the subject, the tone, and whether it is a safe place for a brand to appear. The result is a set of contextual signals a buyer can act on without a single identifier. Read the documentation to see the taxonomy.

What comes back

A ranked topic list, IAB categories, brand-safety flags and sentiment, all from the page text alone. No cookies, no fingerprints, nothing that follows a reader between sites.

What this sheet does not do

Typography stops at the shadow boundary. A component's own text is styled by its recipe, so linking this sheet cannot restyle a neuwo-button label or a neuwo-cta headline. Those are reached through their tokens or their ::part names.

It also styles nothing else: no lists, tables, blockquotes, code or hr. Those are foundation/markdown.css, a separate opt-in sheet scoped to a .neuwo-markdown container, because a list in a nav and a list in an article want different treatment. Everything monospaced on this page is page chrome.
